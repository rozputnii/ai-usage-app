# S2 results (in progress, new PC, account `second`)

Micro-trials, run in batches of at most $20 with `tools/Start-Batch.ps1` (random order, budget
stop). The owner sends the `/usage` reading with every message; readings are logged locally.

## Setup added for S2 (2026-10-11)

- `csharp-lsp@claude-plugins-official` 1.0.0 installed for the account (user scope; owner
  authorization 2026-10-11). Checked in a clone: a haiku run had the LSP tool and found
  `PeakHours` and its two usages through it. Runs before this point (S1, the runner batch) had
  no LSP tool; the runner trial does not use it.
- graphify 0.9.85 (`uv tool install graphifyy`; `graphify install` not run). The graph is built
  once per base outside the measured run with
  `graphify extract <clean clone> --code-only --out C:\aiu-exp\graphify\<base>` (local AST, no
  LLM, no semantic pass): 6 s for `1a8526e`, 4,956 nodes, 17,186 edges. Runs get it through
  `Start-Run.ps1 -CopyIntoClone C:\aiu-exp\graphify\<base>`, git-excluded in the clone.

Base `1a8526e`, primary opus medium, `D-agents.json`; checks restore, C2, C6, C4, C5. Two runs
per variant, $0.78 in total.

| Variant | Cost | Primary calls | Subagent | Wall |

| self | $0.22, $0.22 | 4, 4 | none | 0.8, 0.6 min |

it saves costs about $0.025 and the runner starts at only 7.7k tokens. The checks were quiet and
all passing; a failing check, whose output the primary must read anyway, may change this.

## Exploration (H6, H9)

Base `1a8526e`, haiku low primary that only delegates, six questions X1-X6, two repeats per
variant, 72 runs, $1.14 in total (whole runs). Accuracy scored against the key (2 correct and
complete, 1 partial, 0 wrong) by a sonnet subagent, spot-checked by the operator on X1. Costs
are the scout subagent's own.

| Variant | Accuracy (mean of 2) | X1 | Scout cost | Calls | Cold start | Tool use |
| --- | --- | --- | --- | --- | --- | --- |
| scout-grep (haiku) | 1.75 | 0.5 | $0.0036 | 5.2 | 3,979 | Grep, Read |
| scout-lsp (haiku) | 1.75 | 0.5 | $0.0037 | 5.3 | 4,846 | LSP never called |
| scout-claudemd (haiku, CLAUDE.md) | 1.75 | 0.5 | $0.0043 | 4.9 | 7,987 | LSP never called |
| scout-graphify (haiku) | 1.67 | 0 | $0.0044 | 5.2 | 5,561 | `graphify` in 17 calls |
| Explore (built-in, haiku) | 1.75 | 0.5 | $0.0047 | 3.8 | 18,642 | Grep, Read |
| scout-sonnet (sonnet medium) | 2.00 | 2 | $0.0319 | 3.7 | 4,835 | LSP never called |

- X2-X6 (locate a member or a value): every variant scored 2 in both repeats. Only X1, which
  needs a cause (the fill keeps the default stretch alignment in a star column, so the width
  animation grows it around the centre), separates them: both sonnet runs found it, no haiku
  run did; haiku answers named the right files or a wrong mechanism.
- H6 (lean roles): supported at equal accuracy. The lean scout is about 23% cheaper than the
  built-in Explore (cold start 4k against 18.6k tokens); loading CLAUDE.md costs 4k tokens of
  cold start and 17% more for no accuracy gain.
- H9 (code intelligence): not supported. With the LSP tool present and the prompt saying to
  prefer it, haiku and sonnet scouts never called it in 36 runs; the tool only adds 870 tokens
  of cold start. graphify was used but gave no accuracy gain (worst on X1) at 22% more cost.
- Absolute scout costs are under one cent; what matters in real work is that a scout keeps the
  search out of the primary's context. Rule of thumb from this trial: a haiku lean scout for
  "where is" questions, a sonnet scout for "why" questions.
- Key notes from scoring: X4's effective default is `LedgerPreferences.RefreshMinutes = 5`
  (`LedgerContract.cs`); `DefaultRefreshInterval` seeds the initial state. X6's Codex client only
  carries Retry-After into `CodexException`. Neither changed a score.
