# OMP-native project bootstrap

## Outcome
A fresh OMP session in the Windows repository restores goals and decisions without the previous conversation, presents ranked work and completes a small authorized scope with portable state and truthful verification. This is development infrastructure for AI Usage, not a general-purpose agent platform.

## Scope
Adopt the consolidated English documentation; create minimal native rules, skills, agents and configuration; implement a thin workflow entrypoint and lightweight validator; verify native batching/isolation, owner selection/pause and bounded independent review. Prove a fresh-session, budget-preserving Autopilot handoff using disposable work. Probe unknown APIs before implementing their bridge.

## Non-goals
No Windows product application/solution, provider login or personal secrets, production signing/release manifest, Store, Android, agent server, separate memory database, twenty custom commands or paid service provisioning. AIU-002 delivers the runnable package after bootstrap. Do not merge that milestone into an oversized AIU-001.

## Acceptance criteria
- AC-01: Adopt all 175 original decisions and the added D-176 English-language rule, supersessions, technical audit and deferred backlog without creating a second authoritative backlog. All authored repository documents and prompts are English.
- AC-02: Record actual Windows/OMP stable version, relevant configuration schema, model-role availability and repository path in a redacted preflight report. Do not invent missing setup facts.
- AC-03: A fresh root session actually discovers project configuration, rules and skills and presents the selected goal/eligible work without the old chat.
- AC-04: Interactive selection supports recommended work, another AIU and cancellation, without product edits before selection. Use native OMP UI/commands without shadowing built-ins.
- AC-05: Deterministic validator tests cover invalid IDs/statuses/references/cycles/AC/path escape/overlap and valid fixtures. No network or inference dependency.
- AC-06: Two independent disposable workers execute in isolation and return outputs/diffs; the primary alone integrates. Reject or serialize intentional overlaps and out-of-scope changes.
- AC-07: Pause/resume preserves actual task/handoff/branch state. A paused worker cannot later mutate the parent tree. A crash does not convert in-progress work into done.
- AC-08: A bounded dry run carries authorization and consumption across a feature-to-fresh-session handoff; owner pause and budget stop work. Already completed work is not executed again.
- AC-09: The primary's always-on Advisor is available and read-only. Verify the final reviewer's memory/narrative isolation and that zero findings is valid. No automatic full-review loop.
- AC-10: Test available local critical-transition guards and document their limits. Verify required remote checks/permissions only when a real authorized remote exists. Never claim sandboxing or configured GitHub protection without evidence.
- AC-11: Authored documents, skills, configuration behavior and scripts are portable through Git; profile-specific authentication, model credentials and sessions remain local. No secrets, personal-path dumps or fabricated DCO identity enter the repository.
- AC-12: The completion report separates PASS, FAIL, NOT_RUN and BLOCKED with actual evidence and the next runnable-package item. Publish only command syntax actually verified in the installed OMP environment.

## Completion
AC-03 through AC-09 cannot pass merely because Markdown exists. If the installed stable OMP lacks a required primitive, report the exact gap and minimum bridge needed. Do not claim Autopilot readiness when only interactive behavior was tested.
