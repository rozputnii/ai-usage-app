## Summary

- **Main is red only because of documentation.** Five links in `docs/workflow/ui-ux-audit-2026-10-04/gallery.md` point into the git-ignored `.ai-usage-local`. The validator checks the local disk, not Git, so they pass locally and fail in CI (ANL-02, ANL-08).
- **The red check is the only barrier to publishing the WIP.** Any ordinary push that fixes the links would very likely turn CI green. Under the owner-selected AIU-014 design, that publishes a signed Preview built from the unverified WIP tree to the owner's auto-updating installation (ANL-01, P0). Both product suites already pass at HEAD.
- **AUD-01 root cause, observed on the host.**
  - An audit input without `ScopeAnnotations` deserializes that property as `null` under the .NET 10 System.Text.Json source generator, which overrides the `= []` initializer.
  - `AuditReplay.Open` then throws `System.ArgumentNullException` at `AuditReplay.cs:48`. This happens inside the `App` constructor, before diagnostics exist, so WinUI fails fast with `0xC000027B` and nothing is logged.
  - The exact preserved failing binary reproduces this on the host, and adding `"ScopeAnnotations": {}` removes the crash.
- **Ordinary startup is not affected.** Ordinary `--demo` startup of HEAD passes, and the failing code is reachable only with `--demo --audit-input=...` (`AuditReplay.cs:22`).
- **HEAD at a glance:** deterministic suites PASS 1061/1061 (Infrastructure 870, Presentation 191), validator tests PASS 80/80, Debug build has 0 warnings.
- **Verdict:** HEAD is **not safe to ship today** (section 4). An independent convergence review returned PASS_WITH_CORRECTIONS, and all corrections are applied (section 9).

## 4. Verdict: is HEAD safe to ship?

**No, not as a Preview today.** Reasons, in order of weight:

1. **Authority and boundary.**
   - The AIU-045 [spec](spec.md) forbids owner-app updates and release publication by this task ("No … owner-app installation/update, release publication").
   - Under the owner-selected AIU-014 phase, every green main push publishes automatically and updates the owner's installation: the AIU-014 approval basis is "the owner's 2026-09-22 request for automatic main-push releases", AC-01 says the same, and so do D-157 ("Every green main merge becomes Preview") and the backlog scope note.
   - That design is legitimate, but it conflicts with CONTRIBUTING's release-authorization rule and with the AIU-045 boundary as soon as main carries unverified WIP. Decision AIU045-D1 resolves this.
2. **No CI result.** CI has never validated HEAD. The product suites have not run in CI on any commit after `383644c`. The local PASS above is from one environment, and two Infrastructure tests fail intermittently in CI (ANL-05).
3. **Startup and real-use evidence is thin.**
   - Only Debug, unpackaged `--demo` startup has been observed.
   - Release and packaged startup, and live mode with the owner's real accounts, are NOT_RUN.
   - The WIP changed code on live paths: `LiveLedgerSource`, `LiveLedgerProjection`, `CardVisuals`, `LedgerFormat`, the view models and `LedgerWindow`.
   - An ordinary live-empty smoke failed on a WIP build in the Sandbox and was never explained (ANL-10).
4. **Unfinished, unreviewed work.**
   - AUD-02 is partial and adds a test seam to a production adapter.
   - About 387 lines of WIP audit harness plus 28 hook lines compile into the signed exe (ANL-09).
   - The latest diff has had no review.
   - FIX-11 has only native evidence; FIX-09 and FIX-10 still need their final native reruns.

**In favour of shipping soon:**
- The published `2026.10.404.0` carries the 14 defects FIX-01..FIX-14 (ANL-06).
- HEAD fixes them, with deterministic red→green evidence for 13.
- Both suites pass, and ordinary startup is unaffected by AUD-01.

So the right target is a verified Preview the owner dispatches after tasks T-01..T-03 (section 8), not a frozen main.
