## Findings

### A1-F1 — The documented Git policy contradicts the actual branch/worktree practice and itself
- **Observation:** CONTRIBUTING says to work directly on `main`, not create branches, and push WIP to `main` often. D-196, also in CONTRIBUTING, describes parallel worktrees merged into `main`, and that is what actually happens. The decision register describes a third policy.
- **Evidence:**
  - CONTRIBUTING.md:32-38 says "do not create new branches… Create a branch only when the owner explicitly asks". CONTRIBUTING.md:57-65 (D-196) says "the owner often runs tasks in parallel worktrees… Right before merging".
  - accepted.md D-178 (around line 585) says "The former direct-main default is superseded". D-179 is "a standing task-branch publication instruction, not a direct-main… grant".
  - superseded.md:5 says the automatic-publication amendment "does not restore the earlier direct-main default". CONTRIBUTING's direct-main rule (commit 554e3b1, 2026-09-20) did restore it, without updating D-178 or D-179 (554e3b1 touched CONTRIBUTING only).
  - Memory no-repeated-approval-gates.md:15 says "Worktree branches made by the app get merged into `main` and pushed when work is done".
  - `git log --merges --since=2026-10-01`: 45 merge commits, all into `users/*` or `worktree-agent-*` branches.
  - stage-1-prompt.md:29 calls this effort an "exception to the main-only default".
- **Label:** fact (texts and counts); inference (agents get conflicting instructions).
- **Confidence:** high.
- **Impact:** quality: an agent that follows CONTRIBUTING literally pushes WIP to `main` (see F2). Speed: agents spend effort on "branch vs main" questions; memory reports that the owner was angered by exactly that question.
- **Proposed direction:** write one current Git flow that matches practice, for example: "each task in its own worktree branch; save-point commits on the branch; merge fresh `main`, assign numbers, validate `--final`, merge into `main` and push when verified". Rewrite D-178 and D-179 as a single current decision that points to it, and delete the contradictory sentence in superseded.md:5. The owner must choose the default (see Open questions).
- **KEEP:** no force-push or history rewrite; preserve unrelated work; a commit is a save point, never a PASS upgrade; releases, tags, dispatch and settings changes need explicit authorization; the D-196 numbering mechanics.

### A1-F2 — WIP pushes to `main` meet automatic Preview publication, and the Preview gate conflicts with "push after each meaningful step"
- **Observation:** every green push to `main` signs and publishes a Preview to the owner's auto-updating installation. CONTRIBUTING still asks for frequent save-point pushes to `main` of incomplete work. verification.md also puts a demo-smoke gate before every push to `main`.
- **Evidence:**
  - CONTRIBUTING.md:28 ("Commit and push to `main`… as work progresses"), :33-35 ("Push after each meaningful step… always before ending a session"), :40-43 and :45-49 (every green push publishes).
  - verification.md:50-54 ("the gate applies before pushing to `main`: … `--demo` startup smoke… when `src` changed").
  - README.md:135-140, and the workflow condition at `.github/workflows/*.yml:99` (push to main plus `AIU_PREVIEW_ENABLED`).
  - The same risk was already rated P0 as ANL-01 ("The next green push to main signs and publishes the unverified WIP to the owner's auto-updating installation", AIU-045 analysis-2026-10-05.md:138, :161). The dispatch-only fix (AIU045-D1) was reversed the same day (commit ff1d788).
- **Label:** fact (texts); inference (the risk is live whenever someone follows CONTRIBUTING literally; worktree practice currently masks it).
- **Confidence:** high.
- **Impact:** quality: unverified builds can reach the owner's daily-use app, which is also the owner's only test vehicle under D-190. Speed: agents cannot satisfy "push often" and "smoke before every push to main" together.
- **Proposed direction:** WIP save points go to the task branch, and only verified merges reach `main`. Rewrite the Preview gate as a merge gate. This resolves together with F1.
- **KEEP:** the Preview gate list (demo smoke when `src` changed, primary diff review, CI green before publication), the `AIU_PREVIEW_ENABLED` kill switch, and the rule that save points never use `[skip ci]` (the ANL-03 lesson).
