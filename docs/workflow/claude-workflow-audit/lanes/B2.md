## Findings

### B2-F1 — Every session and subagent loads about 60 skill listings, mostly irrelevant, plus seven unusable connectors and one broken MCP server
- **Observation:** This subagent's context contains:
  - 15 superpowers skills, 8 ux-superpowers, 9 design-superpowers, 6 desktop-commander and 7 `design:*` skills;
  - about 14 claude.ai-synced `anthropic-skills:*` (docx, pptx, xlsx, morning, google-workspace, chrome-browser and others);
  - an MCP notice for seven `plugin:design:*` connectors that need OAuth (asana, atlassian, figma, intercom, linear, notion, slack);
  - a `plugin:desktop-commander` CONNECTION_CLOSED notice.

  Frontmatter sizes: superpowers 2,938 characters, ux-superpowers 11,619 (the 1,536-character cap per skill trims part of it), design-superpowers 2,898, desktop-commander 4,352. That is roughly 4–5k tokens of listings with no use for a WinUI quota app. Subagents get the same listing, and AIU-055 ran up to 11 worker subagents plus reviewers, so the cost multiplies. A long list of auto-trigger descriptions also raises the chance of a wrong skill firing. Examples: ux-superpowers advertises that it should "win over superpowers:brainstorming", and design accessibility-review conflicts with the owner's 2026-10-03 direction to exclude accessibility work.
- **Evidence:** the synced manifest (above); `wc` of `skills/*/SKILL.md` frontmatter per plugin; this session's system-reminder skill and MCP lists; https://code.claude.com/docs/en/skills (listing truncates `description`+`when_to_use` at 1,536 characters).
- **Label:** Clutter / context cost. **Confidence:** High for the inventory, Medium for the token estimate.
- **Impact:** Quality: fewer wrong-skill triggers and less contradictory guidance. Speed: smaller fixed context per session and subagent, and no recurring auth or connection noise.
- **Proposed direction:** Retire ux-superpowers, design-superpowers, desktop-commander and design (F6–F9). Optionally turn off irrelevant synced Anthropic skills with user-level `skillOverrides` (`"off"` or `"name-only"`). Owner settings only, not repo.
- **Verdict:** Retire the four plugins. Trim the synced skills (owner choice).
- **Security/supply-chain:** Fewer third-party prompts and hooks with session permissions.
- **Effort and upkeep:** Minutes in the claude.ai plugin settings or `/plugin`. Less upkeep afterwards.
- **KEEP:** pdf/xlsx synced skills, if the owner uses them outside this repo.

### B2-F2 — superpowers is well maintained, but claude.ai sync updates it without pinning, so its behavior can change under the repo's rules
- **Observation:**
  - Maintenance: obra/superpowers has about 296k stars, last push 2026-10-08 and 324 open issues. Recent releases: v6.4.2 (2026-09-25), v6.4.1 (09-19), v6.3.0 (08-12), v6.2.0 (07-24), v6.1.1 (07-02). The directory listing shows `review: done` by Anthropic.

  - Behavior changes: recent releases changed behavior materially. In v6.4.1, `executing-plans` "no longer stops every few tasks"; plans need separate review before execution; brainstorming ties approval to stages. In v6.4.2 the plan format was rewritten.
  - Repo dependence: repo specs bind to these semantics. AIU-055 `tasks.md:8,23` says "REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development … that section overrides the skill's one-task-at-a-time loop and its stop before merges and pushes". So each upstream release can silently change how a live plan executes.
- **Evidence:**
  - `gh api repos/obra/superpowers` and its releases (2026-10-08);
  - `…/6ba53849…/RELEASE-NOTES.md` v6.4.1 and v6.4.2;
  - https://code.claude.com/docs/en/plugins-reference §version ("a plugin from a marketplace hosted on claude.ai … aren't pinned by this field");
  - `docs/specs/AIU-046,048,053,054,055/tasks.md` headers.
- **Label:** Risk (process drift). **Confidence:** High.
- **Impact:** Quality: the repo's process becomes version-dependent on an external release cadence of about two weeks. Speed: every override section in a spec is rework that exists only to neutralize the plugin.
- **Proposed direction:** Make the repo's process self-contained. Specs should reference repo-owned skills or rules, not `superpowers:*` semantics (F5).
- **Verdict:** Adapt. Do not depend on the live plugin for binding process.
- **Security/supply-chain:** MIT license. Anthropic reviewed the directory listing, but the hook runs bash with session permissions. An optional visual-companion logo fetch sends the version as telemetry (`README.md:399`; opt out with `SUPERPOWERS_DISABLE_TELEMETRY`, `DISABLE_TELEMETRY` or `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`).
- **Effort and upkeep:** See F5.
- **KEEP:** Its methodology content, which is high quality and actively evaluated (planted-defect probes, evals).

### B2-F3 — The SessionStart injection pushes "skill before anything" and ceremony against AGENTS.md autonomy
- **Observation:**
  - What the hook injects: `hooks/hooks.json` runs `run-hook.cmd session-start` on `startup|clear|compact`. It injects the full `using-superpowers/SKILL.md` (3,192 bytes) inside `<EXTREMELY_IMPORTANT>`, about 850–900 tokens, repeated after each clear and compact.
  - What the injected text mandates: "If you think there is even a 1% chance a skill might apply … you ABSOLUTELY MUST invoke the skill". It requires skills "BEFORE any response or action — including clarifying questions, exploring the codebase, or checking files". It also says "Before entering plan mode … invoke the brainstorming skill first", and its red-flags table rejects "The skill is overkill".
  - How it conflicts: AGENTS.md and CONTRIBUTING ask for minimum sufficient process. They say "Available planning tools are optional" and that the agent should "Complete authorized implementation … without repeated approval".
  - Mitigation inside the hook text: it does say "User instructions (CLAUDE.md, AGENTS.md …) take precedence over skills", so the conflict is resolvable, but only by the model reconciling two priority claims every session.
  - Windows: the hook needs Git Bash and silently exits 0 without it (`run-hook.cmd`). Bash is present here.
  - Subagents: the injection did not appear in this subagent's context. `<SUBAGENT-STOP>` also tells dispatched subagents to ignore the skill.
- **Evidence:** `…/6ba53849…/hooks/hooks.json`, `hooks/session-start`, `hooks/run-hook.cmd`, `skills/using-superpowers/SKILL.md`; `CONTRIBUTING.md` §Development procedure step 2; MEMORY "No repeated approval gates".
- **Label:** Conflict. **Confidence:** High.
- **Impact:** Quality: competing top-priority instructions make behavior less predictable. Speed: extra skill loads and announcements on simple tasks. Secondary benchmarks report more tokens on simple tasks (MindStudio).
- **Proposed direction:** Remove the injection by disabling the plugin for this repo (F5). The only alternative that keeps the plugin is a standing precedence block in AGENTS.md, which costs context and still relies on the model's arbitration.
- **Verdict:** Retire the injection (using-superpowers).
- **Security/supply-chain:** The hook runs bash at every start, clear and compact with user permissions. The code is small and readable.
- **Effort and upkeep:** One settings line.
- **KEEP:** None for the injection itself.

### B2-F5 — Selective configuration is possible only per plugin, so the clean route is disable plus vendor
- **Observation:**
  - Plugin-level switches:
    - `enabledPlugins` works at any scope. Synced plugins load as `<name>@synced`, and the docs say "To turn off one synced plugin … set `"<name>@synced": false` in enabledPlugins".
    - Project `.claude/settings.json` overrides user settings and is checked into the repo, so it also applies in every worktree.
    - `syncClaudeAiPlugins: false` stops all sync (user or local scope).
  - Skill-level switches:
    - `skillOverrides` (`on`, `name-only`, `user-invocable-only`, `off`) "does not apply to plugin skills".
    - A permission `deny` on `Skill(superpowers:brainstorming)` may block one plugin skill. The docs show exact-name `Skill(name)` matching, but I did not verify this for namespaced plugin skills.
  - Hook-level switches: the only way to drop a plugin's hook while keeping its skills is `disableAllHooks`, which also kills every other hook. There is no superpowers env switch for the injection. The only `SUPERPOWERS_*` runtime variable found is the telemetry opt-out.
- **Evidence:** https://code.claude.com/docs/en/settings-reference §enabledPlugins, §syncClaudeAiPlugins; https://code.claude.com/docs/en/skills §skillOverrides; grep of `SUPERPOWERS_` in the plugin.
- **Label:** Opportunity. **Confidence:** High for `enabledPlugins` and `skillOverrides` semantics. Medium for the exact synced key name (`superpowers@synced`): the docs state the pattern, but I did not confirm it in `/plugin`.
- **Impact:** Quality: deterministic repo-owned process. Speed: removes the injection and the 15 listings.
- **Proposed direction:** Stage 2, owner decides. (1) Add the adapted repo skills (F4) under `.claude/skills/`. (2) Set `"superpowers@synced": false` in project `.claude/settings.json`, scoped to this repo so other projects keep it. (3) Replace the `REQUIRED SUB-SKILL: superpowers:*` headers in future specs with the repo skill names. Leave historical specs unchanged. Reversible by deleting one line.
- **Verdict:** Adopt this configuration pattern (owner decides).
- **Security/supply-chain:** Reduces third-party code that runs at session start.
- **Effort and upkeep:** About 1 hour of config and docs plus the F4 adaptation work.
- **KEEP:** User-level plugin for other projects.
