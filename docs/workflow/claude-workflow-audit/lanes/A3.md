## Findings

### A3-F1 — Superpowers SessionStart injection overrides the repo's lightweight process and has already cost owner patience

- **Observation:** The superpowers plugin runs a `SessionStart` hook (matcher `startup|clear|compact`) that injects the full `using-superpowers` skill wrapped in `<EXTREMELY_IMPORTANT>`: "If you think there is even a 1% chance a skill might apply … you ABSOLUTELY MUST invoke the skill", "Invoke relevant or requested skills BEFORE any response or action", and "Before entering plan mode … invoke the brainstorming skill first". The downstream skills prescribe artifacts and gates that contradict repo rules: `brainstorming` writes and commits `docs/superpowers/specs/YYYY-MM-DD-<topic>-design.md` and asks the user to review the written spec; `writing-plans` writes `docs/superpowers/plans/…` with "Frequent commits" and assumes a worktree made by `using-git-worktrees`; `subagent-driven-development` writes `.superpowers/sdd/tasks/*`. Repo rules: specs live in `docs/specs/<AIU-ID>-<slug>/` (AGENTS.md); "Available planning tools are optional" (CONTRIBUTING step 2); "without repeated approval for internal steps" (CONTRIBUTING step 3). The skill text itself says CLAUDE.md/AGENTS.md take precedence, but AGENTS.md never names superpowers, so the precedence is never actually invoked.
- **Evidence:** hook `…/6ba53849…/hooks/hooks.json` + `hooks/session-start`; injected body 3,192 bytes + ~250 bytes wrapper. Injection present in 51 of 75 top-level sessions (**fact**; the rest predate installation or are non-startup). Skill invocations across all transcripts: writing-plans 8, systematic-debugging 7, executing-plans 5, test-driven-development 4, subagent-driven-development 3, brainstorming 3, finishing-a-development-branch 2, dispatching-parallel-agents 2, verification-before-completion 1, receiving-code-review 1 (37 total). `docs/superpowers/` never existed in Git history; `.superpowers/` exists in 4 worktrees and is hidden by a local `.git/info/exclude` line (not versioned). Memory `no-repeated-approval-gates.md` records that on 2026-10-07 a superpowers-style written-spec review gate made the owner angry and adds a workaround: "Process-skill review gates (brainstorming spec review, writing-plans execution choice) count as already approved."
- **Label:** fact (hook, text, counts, memory); inference (that the gate in AIU-047 came from the brainstorming skill — the memory names it explicitly, so confidence is high).
- **Confidence:** high.
- **Impact:** quality — conflicting process authority (two spec locations, extra commits, worktree assumptions) invites drift and record duplication; speed — extra skill reads (brainstorming 17.5 KB, executing-plans 20.4 KB, subagent-driven-development 32.6 KB, writing-plans 10.3 KB per invocation) and extra owner approval round-trips; ~850 always-on tokens per session and after every compact.
- **Proposed direction:** Owner decision between (a) disabling superpowers for this project (project-scope `enabledPlugins` override) and keeping the few skills that clearly add value by referencing them on demand, or (b) keeping it enabled and adding one precedence line to AGENTS.md: superpowers skills are optional tools; repo layout, spec location, single-approval rule and Git policy win; no `docs/superpowers` files and no separate written-spec review gate. Option (b) is the minimal change; (a) removes the always-on pressure entirely. Then retire the memory workaround.
- **KEEP:** the *ideas* the owner already uses and that align with repo rules — systematic debugging (root cause before fix), verification-before-completion (evidence before claims; matches AGENTS "Report PASS, FAIL, NOT_RUN…"), red-green testing. These are low-conflict and were the most-invoked skills after planning.
